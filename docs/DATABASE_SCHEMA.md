## 📌 1. النظرة العامة على طبقة البيانات الحالية

يعمل النظام حالياً بنمط **معماري محلي أولاً (Local-First Architecture)** يعتمد على:
1. **ذاكرة التطبيق الموحدة (In-Memory State):** عبر `React Context API` (`AppContext.tsx`) لإدارة الحالة اللحظية للواجهات.
2. **التخزين المحلي الآمن (Client Storage):** حفظ بيانات التقارير، المرضى، وإعدادات العيادة في `localStorage` للمتصفح أو WebView الخاص بالأندرويد.
3. **محرك النسخ الاحتياطي الذاتي (JSON Database Backup):** تصدير واستيراد كامل قاعدة البيانات بصيغة JSON مهيكلة للتبادل السهل أو الاستعادة عند تغيير الجهاز.
4. **الربط السحابي الخارجي (Cloud Database):** **[بحاجة للتحديث]** — لم يتم ربط خادم خارجي مثل PostgreSQL أو Firestore بعد؛ حيث يعمل التطبيق مستقلاً دون اتصال.

## 📊 2. الجداول ونماذج البيانات (Entities & Interfaces)

يتم تعريف كافة نماذج البيانات بدقة في ملف `src/types/index.ts`:

### 1. نموذج المريض (`Patient`)
يمثل سجل المراجع الأساسي في العيادة أو المختبر.

| الحقل (Field) | النوع (Type) | إجباري؟ | الوصف والتفاصيل |
|---|---|---|---|
| `id` | `string` | نعم | المعرف الفريد للمريض (مثل: `pat1`, `pat_17140001`) |
| `name` | `string` | نعم | الاسم الثلاثي أو الرباعي الكامل للمريض |
| `age` | `number` | نعم | عمر المريض بالسنوات (يُستخدم لحساب المعدلات الطبيعية) |
| `sex` | `'M' \| 'F'` | نعم | الجنس: `M` (ذكر) أو `F` (أنثى) للمطابقة المرجعية |
| `phone` | `string` | اختياري | رقم هاتف أو واتساب المريض للتواصل وإرسال التقارير |
| `createdAt` | `string` | نعم | تاريخ تسجيل المريض لأول مرة (`YYYY-MM-DD`) |

### 2. نموذج التقرير المخبري (`LabReport`)
يمثل الفاتورة وتقرير الفحص الطبي المتكامل للعينة.

| الحقل (Field) | النوع (Type) | إجباري؟ | الوصف والتفاصيل |
|---|---|---|---|
| `id` | `string` | نعم | المعرف الفريد للتقرير في النظام (مثل: `rep_533`) |
| `labNumber` | `string` | نعم | رقم السجل المخبري الرسمي المطبوع (مثل: `LAB-000533`) |
| `patientId` | `string` | اختياري | المعرف المرجعي للمريض المرتبط به الفحص (Foreign Key) |
| `patientName` | `string` | نعم | اسم المريض (مخزن لتسريع العرض والطباعة) |
| `patientAge` | `number` | نعم | عمر المريض وقت إجراء الفحص |
| `patientSex` | `'M' \| 'F'` | نعم | جنس المريض وقت إجراء الفحص |
| `doctorName` | `string` | نعم | اسم الطبيب المعالج أو المحيل للعينات |
| `reportDate` | `string` | نعم | تاريخ إجراء التقرير (`YYYY-MM-DD`) |
| `status` | `'completed' \| 'pending' \| 'draft'` | نعم | حالة التقرير: معتمد ومنجز، قيد الانتظار، أو مسودة |
| `hematologyLeft` | `TestResultItem[]` | نعم | مصفوفة نتائج تحاليل أمراض الدم - العمود الأيمن في التقرير |
| `hematologyRight` | `TestResultItem[]` | نعم | مصفوفة نتائج تحاليل أمراض الدم - العمود الأيسر في التقرير |
| `biochemical` | `TestResultItem[]` | نعم | مصفوفة نتائج تحاليل الكيمياء الحيوية والوظائف الحيوية |
| `serological` | `Record<string, string>` | نعم | خريطة تحاليل الأمصال والمناعة (اسم الفحص -> النتيجة) |
| `notes` | `string` | اختياري | ملاحظات وتوصيات الطبيب المخبري المرفقة بالتقرير |

## 🔗 3. مخطط العلاقات بين الكيانات (Entity-Relationship Diagram)

```text
+-----------------------+              +-------------------------+
|        PATIENT        |  1        N  |       LAB_REPORT        |
+-----------------------+--------------+-------------------------+
| id (PK)               |              | id (PK)                 |
| name                  |              | labNumber               |
| age                   |              | patientId (FK -> Pat)   |
| sex                   |              | doctorName              |
| phone                 |              | reportDate              |
| createdAt             |              | status                  |
+-----------------------+              | notes                   |
                                       +-------------------------+
                                                    |
                                                    | 1
                                                    | contains
                                                    | N
                                       +-------------------------+
                                       |    TEST_RESULT_ITEM     |
                                       +-------------------------+
                                       | testId (FK -> TestDef)  |
                                       | testName                |
                                       | result                  |
                                       | unit                    |
                                       | normalRange             |
                                       | isAbnormal (Flag)       |
                                       +-------------------------+
```

## 🧠 4. آلية التحقق التلقائي من القيم الحرجة (Abnormal Flagging Logic)

عند إدخال أي قيمة في شاشة الفواتير (`AddInvoiceScreen.tsx`):
1. يتم جلب تعريف الفحص من جدول المرجع `referenceRanges.ts`.
2. يتم التحقق من جنس المريض (`patientSex`):
   - إذا كان ذكراً ومحدداً له `maleMin` و `maleMax`: تُقارن القيمة مع هذين الحدين.
   - إذا كانت أنثى ومحدداً لها `femaleMin` و `femaleMax`: تُقارن القيمة مع هذين الحدين.
   - إذا كان نطاقاً عاماً (`min` و `max`): تُقارن القيمة معهما.
3. إذا كانت القيمة خارج النطاق المقبول، يتم تعيين `isAbnormal = true` فوراً، وتلوين النتيجة باللون الأحمر وتنبيه المستخدم لتفادي الأخطاء الطبية قبل اعتماد التقرير.
